### Micro-Feature 21: VLC State & Math Sync

- **Real-time Playback Time (4.9):** Implemented a high-performance polling engine to fetch live `time` and `length` from VLC via HTTP. A thread-safe `live_playback_time` variable was added to `AppState` using an `Arc<RwLock<f64>>` to allow the React frontend to continuously track progress natively. The fetcher intelligently detects sudden leaps in timestamp data to temporarily jump into "high-res mode" (polling at 500ms intervals instead of 5s) to guarantee that user scrubbing always logs exact positions accurately. Deserialization was hardened utilizing a strictly typed `VlcStatus` struct featuring `Option<f64>` wrapping to prevent hard panics when VLC drops status nodes.
- **Dynamic File Overrides (4.10):** Engineered logic to dynamically override TMDB's generic runtime length with the exact local file's length if a deviation of > 2 minutes is detected across a stabilized 3-poll rolling buffer. If a file returns an anomalous length of 0.0 (e.g. streaming or corrupted headers), the engine emits a discrete `vlc-livestream-fallback` event so React can adjust the user interface contextually.
- **Spam-Click Debouncing (4.11):** Established robust playback monitoring that actively filters out rapid play/pause spamming from generating repetitive `History` logs, via a 1000ms stability gate. True `stopped` states, however, instantly bypass this gate to reliably trigger a "Session Closure" protocol that cleanly resolves DB commits before the thread is dropped.
- **Mathematical Precision (4.12):** Converted tracking math strictly to high-precision 64-bit floats bounded via explicit clamping (`f64::clamp(0.0, 1.0)`) to nullify mathematical drift or NaN division errors. Further incorporated dynamic short-form completion threshold adjustments: clips under 5 minutes now consider any position past the `length - 30s` mark as 100% complete, offering a tighter UX feel for non-cinematic media.
- **Console Terminal Fix:** Addressed a critical graphical UI annoyance on Windows OS where `cmd.spawn()` triggered a lingering VLC command terminal prompt overlay. Successfully injected `creation_flags(0x08000000)` into the underlying OS layer by correctly transforming a specialized `std::process::Command` into the required `tokio::process::Command`.
