VLC Process Spawning: The code already spawned VLC via std::process::Command::new("vlc").arg("--extraintf=http").spawn().
What I implemented:
Zero Background CPU Logic (Async Refactor in vlc.rs):

Replaced std::process::Command with tokio::process::Command: Now, the Rust backend holds an asynchronous child process handle.
Implemented tokio::select!: Instead of an infinite while true loop with a blocking std::thread::sleep(5) that held up an active thread, the heartbeat now sits in an async loop where it concurrently waits for either the VLC process to close (proc.wait()) or a 5-second tokio::time::interval(Duration::from_secs(5)) tick. This allows the OS to completely park the thread when VLC is running, using literally 0% CPU.
Idle / Zombie Detection: I added a consecutive_failures counter. If the HTTP request to VLC (get_vlc_status) fails 3 times in a row, the thread assumes VLC crashed or the user force-quit it, and it safely aborts the loop to prevent dangling zombie threads.
Async HTTP Polling: Refactored the reqwest client in vlc.rs to use its async Client instead of the blocking client.
Graceful Panic Handling & Error Architecture (error.rs & commands.rs):

Added the thiserror crate: Created a new file src-tauri/src/error.rs containing a custom AppError enum.
Structured Error Wrapping: AppError wraps common failure types like rusqlite::Error, reqwest::Error, std::io::Error, and serde_json::Error. It also implements serde::Serialize so that if an error occurs, it returns a clean, user-friendly string to the React frontend (e.g., "A database error occurred") rather than a frightening Rust backtrace.
Global catch_unwind Boundary: Wrote a helper function handle_panic(|| { ... }) that wraps the contents of every Tauri command. If a raw array index out-of-bounds error or unhandled panic occurs, it catches the panic before it takes down the Tauri application shell.
Local Logging: Inside the panic catcher, it intercepts the raw panic string and appends it locally to watchmark.log inside your WatchMark application data folder with a timestamp so you can debug production errors without users seeing them.
Audited .unwrap() Calls: I went through commands.rs, scanner.rs, and tmdb.rs and replaced dangerous .unwrap() and .expect() calls with standard ? error propagation or safe .unwrap_or() defaults, ensuring the commands safely map to Result<..., AppError>.
